# RoboMaster EP 地面六格杯子/瓶子分类程序

本目录实现实验 3 的真机部分：RoboMaster 在固定起点拍摄地面六格，使用 YOLO 识别杯子、瓶子、鼠标或空格；底盘横移/前进完成夹爪对准，机械臂仅前伸和升降；杯子送往左侧，瓶子送往右侧；每处理一件都回到原始拍摄位并重新识别。

程序直接调用 RoboMaster Python SDK，不依赖 ROS 2，本版不包含仿真。模型类别已核对为 `0: cup`、`1: mouse`、`2: bottle`。程序只抓取 `cup` 和 `bottle`，`mouse` 记录为 `unsupported`。

2026-09-12 的 RoboMaster 实拍表明，当前权重会把实验用金属马克杯稳定误判成 `bottle`，而两只真实瓶子仍判为 `bottle`，因此不能交换类别编号。当前固定场景启用了 `model.shape_guard`：对 YOLO 已检出的杯子/瓶子，检测框高宽比不大于 `1.75` 时按杯子处理，不小于 `2.00` 时按瓶子处理，中间区间标为 `cup_bottle_ambiguous` 并禁止抓取。该规则仅适用于杯子直立、瓶子竖直、相机回中姿态固定的本实验；它是实操保护措施，不等于模型已经修复。通用解决方案是补采该 RoboMaster 摄像头、当前光照和当前杯型的数据后重新训练或微调模型。

## 一、规定的地面坐标与摆放位置

机器人起点中心为原点 `O=(0,0)`：

- `+X`：机器人初始朝向，也就是向物体区前进；
- `+Y`：机器人初始姿态的右侧；
- `-Y`：机器人初始姿态的左侧；
- 所有距离单位均为米；
- 每个物体格画成 `0.20 m × 0.20 m`，物体竖直放在格子中心。

```text
                         +X（机器人前方）

        G4                 G5                 G6       远排 X=0.82 m
   (0.82,-0.40)       (0.82,0.00)        (0.82,+0.40)

        G1                 G2                 G3       近排 X=0.55 m
   (0.55,-0.40)       (0.55,0.00)        (0.55,+0.40)

 杯子分类盘                                                     瓶子分类盘
  (0,-0.40)             ← -Y      O      +Y →                 (0,+0.40)
                                   ↑
                              机器人面向 +X
```

六个物体的中心坐标如下：

| 格子 | 顺序 | X 前方 | Y 右方 | 相对机器人 |
|---|---:|---:|---:|---|
| G1 | 1 | 0.55 m | -0.40 m | 近排左 |
| G2 | 2 | 0.55 m | 0.00 m | 近排中 |
| G3 | 3 | 0.55 m | +0.40 m | 近排右 |
| G4 | 4 | 0.82 m | -0.40 m | 远排左 |
| G5 | 5 | 0.82 m | 0.00 m | 远排中 |
| G6 | 6 | 0.82 m | +0.40 m | 远排右 |

左、右分类区建议使用至少 `0.40 m × 0.40 m` 的浅盘或周转箱，中心分别放在 `(0,-0.40)` 和 `(0,+0.40)`。机器人只原地转向，不向分类区前进，因此放置点必须处于机械臂转向后的实际可达范围内。同一类别的多个物体会投放到同一个盘内。马克杯把手统一朝远离机器人方向（`+X`），瓶子竖直放置，减少夹爪接触把手或倾倒的概率。

近排与远排中心距为 `0.27 m`。每格沿 X 方向宽 `0.20 m`，所以两排格子边缘之间留下 `0.07 m`（7 cm）间隙。上述坐标和底盘位移已写入 `sorter_config.json`，并另存为 `ground_layout.csv`。它们是首轮场地方案，不等于已经在你的地面、轮胎和载荷条件下完成标定。

## 二、程序实际执行逻辑

每次循环严格执行：

1. 机器人处于原点、面向 `+X`。真机执行模式先强制机械臂 `recenter()`，等待 `0.8 s`，丢弃 3 帧，再连续拍摄 12 帧；这样安装在机械臂上的摄像头每次都从同一姿态观察六格。
2. 对 YOLO 杯子/瓶子框执行上述外形安全校验，再把检测框中心映射到六个固定 ROI，并投票得到 `candidate`、`empty`、`unsupported`、`uncertain` 或 `ambiguous`。青色物体检测框只显示最终类别名称；完整置信度、命中帧数和状态仍写入日志。根据现场日志中远排小目标常落在 `0.45-0.55` 附近的情况，模型输出阈值现由 `0.55` 调为 `0.45`；12帧扫描、至少5帧命中和 `0.70` 投票比例保持不变，用多帧稳定性继续限制误检。
3. 按 `G1→G2→G3→G4→G5→G6` 选择第一个稳定杯子或瓶子，不再按置信度跨行抢先处理。
4. 底盘先左右平移到该列，再前进，使物体进入机械臂的实测抓取位置；当前把机械臂基座前置偏移和机械臂伸出合并为“底盘中心到物体约 `0.40 m`”。
5. 机械臂执行“先下降→向前伸至物体→夹紧→抬起→回中”。杯子使用比瓶子更低的独立抓取高度。
6. 底盘沿原路径倒序返回原始拍摄位。
7. 杯子：原地左转 `90°`，机械臂向左侧分类盘放下；原地右转 `90°` 回到原姿态。
8. 瓶子：原地右转 `90°`，机械臂向右侧分类盘放下；原地左转 `90°` 回到原姿态。
9. 在原始拍摄位重新扫描；只有源格稳定为空才计为成功。
10. 重复上述流程，直到六件处理完或没有安全可执行目标。

远排具有通道联锁：`G4` 只有在 `G1` 为空时可进入，`G5` 要求 `G2` 为空，`G6` 要求 `G3` 为空。如果近排同列是鼠标、检测不确定或抓取失败，后排该通道会记录为 `rear_lanes_blocked`，机器人不会穿过障碍物。

## 三、底盘路线的由来

根据连续底盘实测，近排和远排现在分别采用独立的现场修正量：

- 近排 G1-G3 在上一版 `0.07 m` 基础上再少前进 `0.01 m`，当前为 `0.06 m`；
- 远排 G4-G6 在上一版 `0.44 m` 基础上再多前进 `0.04 m`，当前为 `0.48 m`；
- 左列横移 `-0.27 m`，中列不横移，右列横移 `+0.27 m`；
- 每条回程保持为去程的逆序反向动作：近排前进/后退均为 `0.06 m`，远排前进/后退均为 `0.48 m`。

六格的地面中心坐标仍保持近排 `X=0.55 m`、远排 `X=0.82 m`，但底盘前进量已按两排的现场误差分别标定，不再强制保持 `0.27 m` 的路线差值。应分别复测 G2 和 G5，再依据夹爪与物体中心的剩余误差调整近排或远排。

麦克纳姆轮在不同地面会打滑，开环里程有累积误差。这些数值必须通过地面胶带标记和低速实测修正，不能只凭计算直接进行满流程抓取。

## 四、已填写的 12 个名义机械臂点

常见 11 oz 直筒陶瓷马克杯大约高 `95-96 mm`、杯身直径约 `76-82 mm`。可参考 [Spoke Custom（3.75 × 3.2 英寸）](https://www.spokecustom.com/product-page/ceramic-coffee-mug-11oz)、[Shutterfly（3.75 英寸高、3 英寸直径）](https://www.shutterfly.com/ideas/coffee-mug-sizes//) 和 [Iron Horse（9.6 cm 高、8.2 cm 直径）](https://ironhorseroasterscoffee.com/products/white-glossy-mug)。这些尺寸只支持“从杯身下半部横向夹持、瓶子也在相近高度夹持”的策略，**不能从物体尺寸直接计算 RoboMaster 的绝对机械臂坐标**。

本项目已有单杯和单瓶测试使用过一组机械臂名义点。根据现场反馈，杯子抓取高度相对最初值累计下调 `45 mm`，杯子分类盘放置点单独下调 `5 mm`；瓶子抓取和瓶子放置路径保持不变。配置已改为 `class_specific_ground_v2` 且 `shared_by_classes=false`。12 个点已经全部写入 `sorter_config.json`：

| 用途 | 物体/分类盘 | 预备点 `[x,y] mm` | 接触/放置点 `[x,y] mm` | 抬升/撤回点 `[x,y] mm` |
|---|---|---:|---:|---:|
| 抓取 | 杯子 | `[0,-60]` | `[205,-60]` | `[180,100]` |
| 抓取 | 瓶子 | `[0,-15]` | `[205,-15]` | `[180,100]` |
| 放置 | 杯子分类盘 | `[180,100]` | `[205,-15]` | `[150,110]` |
| 放置 | 瓶子分类盘 | `[180,100]` | `[205,-10]` | `[150,110]` |

这里一行包含 3 个二维点，共 `4 × 3 = 12` 个机械臂点。`x` 表示水平伸出、`y` 表示垂直方向，单位毫米；RoboMaster SDK 的 `moveto(x,y)` 是相对机械臂上电初始位置的绝对坐标，详见 [RoboMaster Python SDK 机械臂文档](https://robomaster-dev.readthedocs.io/en/latest/python/robotic_arm.html)。网上的杯子尺寸不知道机械臂上电零点、安装高度、夹爪指尖位置、地面高度及杯把方向，因此这些数值只能作为低速调试初值。

配置中的两道真机安全锁当前均已由操作者明确解除：

- `"calibrated": true`；
- `"arm_point_profile.verified_on_this_robot": true`。

因此 `python3 desktop_sorter.py --execute` 不再被配置锁拒绝，并会启动完整真机流程。解除标志只是允许执行，不等同于 12 个机械臂点已经通过物理验证；首次运行仍须清空周围、限制为一个物体并准备立即断电或急停。

## 五、真机标定顺序

1. 按上表在平整地面贴出六格和两个分类盘中心，标记机器人四轮或底盘外框的固定起点。
2. 摄像头安装在机械臂上，因此只能在机械臂回中姿态标定 ROI。运行回中预览，程序会先等待 5 秒，再让机械臂回中并拍摄；近排应位于图像下部 `G1-G3`，远排位于图像上部 `G4-G6`，按现场画面修改六个 `roi_norm`。

   根据现场画面，G4-G6 已统一向下平移画面高度的 `0.05`：纵向范围由 `[0.10,0.45]` 改为 `[0.15,0.50]`。近排仍从 `0.55` 开始，因此两排 ROI 之间保留 `0.05` 的非重叠间隔；720p 画面中一次平移约为 36 像素。

   ```bash
   python3 desktop_sorter.py --preview-recenter
   ```

   `--preview-recenter` 只允许机械臂执行一次 `recenter()`；不会平移/旋转底盘，不会开合夹爪，也不会抓取识别到的物体。回中后等待 `camera.scan_settle_s=0.8 s`，再丢弃 `camera.warmup_frames=3` 帧并进行一次识别，因此画面姿态与正式执行一致。仍需清空机械臂运动范围并准备物理急停。

   如需完全零运动的静态检查，仍可使用 `--preview-only`；该模式不会回中，并在日志中写入 `scan_pose_not_enforced`，所以不应使用任意机械臂姿态下的静态预览来标定正式 ROI。

3. 空载逐条测试底盘路线。`--test-route` 只执行指定路线的去程和回程，不会启动相机、机械臂或夹爪。例如：

   ```bash
   python3 desktop_sorter.py --execute --test-route G1
   python3 desktop_sorter.py --execute --test-route G4
   python3 desktop_sorter.py --execute --test-route cup-bin
   python3 desktop_sorter.py --execute --test-route bottle-bin
   ```

   每一条底盘平移或旋转指令完成后，程序还会按照
   `safety.chassis_step_settle_s` 等待；当前为 `2.0 s`。这包括“后退后横移”
   这样的相邻动作，用于给底盘制动和姿态稳定留出时间。

   依次测试 `G1-G6`。检查物体中心是否进入夹爪的实际可达位置，并检查每条回程是否回到起点标记。测试命令现在还会打印 SDK 里程计的起点、去程终点、回程终点和残差。若物理残差与 SDK 残差一致，可继续用位置反馈做小量纠偏；若 SDK 接近零而地面仍差数厘米，则主要是轮胎打滑，不能靠里程计消除，需改善地面/轮胎条件或增加地面标记视觉回零。此模式会真实移动底盘，所以同样需要净空区和物理急停，但不要求先把 `calibrated` 改成 `true`。

   现场测试表明固定增加2厘米会造成后退过量，因此该固定补偿已撤销。当前验证不要添加 `--correct-home`。

   G1-G6 路线测试可以显式增加一次保守回零修正：

   ```bash
   python3 desktop_sorter.py --execute --test-route G2 --correct-home
   ```

   该选项会在位置订阅稳定 `0.6 s` 后记录起点，完成正常去程/回程后，根据 SDK 的 X/Y 残差再移动一次。修正增益为 `0.6`，单轴最多 `0.05 m`，残差不超过 `0.015 m` 时不动；残差超过 `0.20 m` 或航向误差超过 `5°` 时拒绝修正。执行额外移动前有 `3 s` 提示。当前只允许 G1-G6 路线测试使用，不会自动影响正式分类或分类盘路线。
4. 底盘对准空的 G2 格后，先测试杯子路径 `[0,-60] → [205,-60] → [180,100]`。机械臂回中后先在 `x=0` 处下降到杯子抓取高度，再保持高度水平伸到杯子；先让夹爪远离物体观察轨迹并确认不会碰底盘、地面或杯子，再放入空杯测试。
5. 用尺寸接近上述范围的空马克杯测试。杯把朝 `+X`、远离机器人；应夹住杯身而不是杯把、杯沿或杯底。
6. 用空瓶测试路径 `[0,-15] → [205,-15] → [180,100]`。机械臂同样先下降再水平伸出；如果瓶身下部过细、过软或容易打滑，应继续单独标定瓶子点，不能同步修改杯子路径。
7. 左转面对杯子盘后低速确认杯子放置路径 `[180,100] → [205,-15] → [150,110]`；右转面对瓶子盘后确认瓶子放置路径 `[180,100] → [205,-10] → [150,110]`。分类盘边缘不得进入夹爪轨迹。
8. 当前两个执行标志已按操作者要求设为 `true`。完成逐点确认、ROI、全部底盘路线以及单杯与单瓶测试后，应把实际结果记录下来；若中断标定或发现任一点不安全，应立即将相应标志重新设为 `false`。

配置中的 `500 mm` 只是防止误填数量级的程序保护，不代表真实可达范围。实机调试必须空载优先、低速、单点推进，并保留安全员和物理急停。

## 六、安装与运行

Jetson 上先使用与 JetPack 匹配的 CUDA 版 PyTorch/Torchvision，再安装程序依赖，避免通用安装命令覆盖已有 CUDA 版本。程序已兼容当前 RoboMaster 环境的 Python 3.8.20；建议使用 Python 3.8 或更高版本：

```bash
python3 -m pip install ultralytics robomaster
```

检查 JSON、路线和类别配置，不连接机器人：

```bash
python3 desktop_sorter.py --validate-config
```

连接 RoboMaster 热点后，先只测试 SDK 连接。这个命令不会启动相机、YOLO、底盘、机械臂或夹爪：

```bash
python3 desktop_sorter.py --connection-test
```

AP 直连模式下，Jetson/电脑应取得 `192.168.2.x` 地址，机器人通常为 `192.168.2.1`。如果仍在校园网或其他网段，程序会在进入旧版 SDK 前直接报出检测到的本机地址，避免 SDK 内部产生难读的连锁异常。

连接机器人，让机械臂回中后只识别和记录：

```bash
python3 desktop_sorter.py --preview-recenter
```

该命令会在 5 秒提示后移动机械臂到回中位置，但不会移动底盘、开合夹爪或执行抓取。完全零运动预览则使用 `python3 desktop_sorter.py --preview-only`。

标定全部通过后，首次仅抓一件，并由一人随时准备物理急停：

```bash
python3 desktop_sorter.py --execute --max-objects 1
```

单件杯子、单件瓶子都成功后，再运行完整六件：

```bash
python3 desktop_sorter.py --execute --max-objects 6
```

## 七、文件与日志

- `desktop_sorter.py`：检测、通道联锁、动作状态机和 RoboMaster SDK 控制。
- `sorter_config.json`：地面坐标、ROI、底盘路线、机械臂点和安全参数。
- `ground_layout.csv`：可打印/测量的场地中心坐标表。
- `best.pt`、`MODEL_INFO.md`：三分类权重及已核对的类别/哈希。
- `tests/test_desktop_sorter.py`：不连接机器人即可执行的逻辑测试。
- `CODE_REVIEW.md`：本轮执行链路自审、已修复问题和真机失败原因清单。

每次运行写入 `logs/run_日期_时间/`：

- `task_log.jsonl`：识别、通道阻塞、抓取、放置和错误事件；
- `scan_*.jpg`：带六格、检测框和状态的证据图；
- `task_summary.json`：源格清空验证通过的数量、类别和失败格。

源格为空只能证明物体已被拿走，不能单独证明物体落在正确分类盘。正式验收仍应拍摄全场视频，能同时看到六格、机器人和两个分类区。

## 八、已知限制

- 这是固定格、固定路线方案，不具备任意位置三维定位和动态避障能力。
- 开环底盘位移会受轮胎打滑、电量和地面材质影响；每轮实验开始前都应复核回零误差。
- 摄像头固定在机械臂上；正式执行会在每次扫描前回中，但机械臂回中重复精度、支架松动、线缆拉扯和停止后的振动仍会使画面偏移。ROI 应保留合理边界，不能贴着物体检测框设置。
- 模型之外的未知物体可能没有检测框，从而被当成空格；鼠标则会明确记录为 `unsupported`。
- `shape_guard` 只利用检测框外形，不适合横放瓶、细长杯、保温杯、被遮挡物体或明显改变后的相机姿态；比例落在 `1.75-2.00` 的拒绝区时程序不会抓取。更换杯瓶外形后必须重新采样验证阈值，不能直接沿用。
- 夹爪 `normal` 状态只是“可能夹住宽物体”的启发式证据，不是力传感器。
- 杯子抓取点已单独下调到 `[205,-60]`，瓶子为 `[205,-15]`；两者都只是当前实测修正值，更换杯瓶尺寸后仍需分别验证。
