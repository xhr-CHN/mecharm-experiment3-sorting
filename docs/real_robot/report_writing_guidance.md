# 实机验证部分报告撰写建议

## 一、建议章节结构

### 1. 实机系统组成

说明 RoboMaster EP 底盘、机械臂、夹爪、臂载相机、YOLO模型和 Python 控制程序。当前程序直接调用 RoboMaster Python SDK，不依赖 ROS 2。

### 2. 视觉识别与固定区域映射

说明模型类别为 `0: cup`、`1: mouse`、`2: bottle`，程序只抓取杯子和瓶子，鼠标记录为不支持目标。相机回中后连续采集12帧，置信度阈值为0.45，至少5帧命中且投票比例不低于0.70。检测框中心映射到 G1 至 G6 六个固定区域。

当前杯型在实拍中可能被模型误判为瓶子，因此程序增加固定场景外形保护：检测框高宽比不大于1.75时按杯子处理，不小于2.00时按瓶子处理，中间区域拒绝抓取。报告应将其写成现场保护规则，不要表述为模型已经重新训练或泛化问题已经解决。

### 3. 场地布局与安全约束

近排 G1 至 G3 的中心前向距离为0.55 m，远排 G4 至 G6 为0.82 m，左右列横向坐标为正负0.40 m。程序按 G1 到 G6 的顺序选择目标。远排设置通道联锁，例如 G4 仅在 G1 为空时允许进入，防止机器人穿过近排障碍物。

底盘实际路线采用现场修正量：左右列横移0.27 m，近排前进0.06 m，远排前进0.48 m。应说明麦克纳姆轮打滑、地面材质、电量和负载会影响开环位移。

### 4. 抓取与分类动作流程

程序流程为机械臂回中、视觉扫描、候选规划、底盘对准、机械臂抓取、原路返回、转向分类区、放置物体、返回初始姿态和源格复扫。杯子送往左侧，瓶子送往右侧。

杯子抓取点为 `[205, -60] mm`，瓶子抓取点为 `[205, -15] mm`。这些坐标是当前机器人和当前物体条件下的现场修正值，不是由物体尺寸直接计算出的通用坐标。

### 5. 实验结果与材料对应

- 六格视觉结果：引用 `05_图像与视频证据/六格同时识别结果.png`。
- 双物体实机过程：优先查看 `05_图像与视频证据/双物体抓取原始录像.mp4`，也可使用 `双物体抓取_PPT内嵌剪辑素材.mp4` 截取关键帧。
- 程序运行记录：引用 `07_报告辅助材料/主程序运行汇总.csv`，需要追溯时引用对应运行目录。
- 程序逻辑验证：引用 `07_报告辅助材料/离线单元测试结果.txt`。

可以表述为：系统已实现六格视觉识别、固定区域映射、安全候选选择、杯瓶分类动作和动作后复扫；现有视频展示了一次杯子与瓶子的双物体实机流程。

不要表述为：六件物体连续抓取已完成正式验收，或者根据连续调试日志计算出了可推广的成功率。

### 6. 问题分析与改进方向

建议讨论模型对当前杯型的误分类、固定ROI对相机姿态的依赖、开环底盘回零误差、夹爪状态缺少力传感器验证，以及现有视频仅覆盖双物体流程。下一步可补采当前相机和杯型数据，重新训练模型，并进行统一条件下的六物体连续测试。

## 二、关键代码位置

文件：`02_核心程序与模型/desktop_sorter.py`

- `apply_shape_guard`：约第70行，杯瓶外形保护规则。
- `validate_config`：约第244行，配置与安全锁检查。
- `point_to_grid`：约第485行，检测中心到六格的映射。
- `plan_candidates`：约第524行，优先级与远排通道联锁。
- `scan_scene`：约第970行，多帧检测、投票和日志记录。
- `sort_one`：约第1037行，单件物体的抓取与分类动作。
- `run_task`：约第1121行，观察、决策、执行和复扫主循环。
- `main`：约第1339行，命令行入口和运行模式选择。

## 三、可直接引用的参数

- 输入分辨率：1280 × 720，相机源为 RoboMaster 臂载相机。
- YOLO推理尺寸：800。
- 置信度阈值：0.45，IoU阈值：0.70。
- 每次扫描：12帧，至少5帧命中，投票比例不低于0.70。
- 目标类别：杯子和瓶子；鼠标不执行抓取。
- 单次任务上限：6件。
- 底盘动作后稳定等待：2.0 s。
- 执行前安全倒计时：5.0 s。

以上参数均来自当前 `sorter_config.json`，更换机器人、相机姿态、地面或物体后需要重新标定。
